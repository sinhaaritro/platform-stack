# NAS Platform Matrix — TrueNAS vs Bare Proxmox

> **Tier:** Tier 4 — User Data (supporting reference)
> **Role:** Compares what a **base TrueNAS** appliance provides out of the box against a **bare Proxmox (Debian)** host, and how the `nas_server` role realises each capability per backend.

The host-level NAS is driven by a single, platform-independent config shape — each node's `storage` var, generated by OpenTofu from `topology.nodes.<node>.storage`. The `nas_server` role reads it and dispatches on `storage.backend` (`proxmox` or `truenas`). See [NFS.md](./NFS.md) and `nas-iac-codification-plan.md`.

---

## What TrueNAS provides vs what Proxmox must build

Present on **base TrueNAS** (configure purely via API; never edit files) but **absent on bare Proxmox** (must be installed + configured by IaC):

| Capability | Base TrueNAS | Bare Proxmox | IaC (TrueNAS) | IaC (Proxmox) |
|---|---|---|---|---|
| ZFS kernel + userland | ✅ | ✅ (ships with PVE) | API | `community.general.zpool/zfs` |
| Pool create/import | ✅ middleware | ⚠️ manual `zpool` | API `/pool` | `zpool` module |
| Dataset + props/quotas | ✅ | ✅ manual | API `/pool/dataset` | `zfs` module |
| **NFS server** | ✅ included | ❌ `apt install nfs-kernel-server` | API `/sharing/nfs` | apt + `/etc/exports` template |
| **SMB/Samba** | ✅ included | ❌ `apt install samba` | API `/sharing/smb` | apt + `smb.conf` template |
| **Share account** | ✅ accounts | ❌ `useradd` + `smbpasswd` | API `/user` | `user` + `smbpasswd` |
| **Periodic snapshots** | ✅ | ❌ none | API `/pool/snapshottask` | `zfs snapshot` + timer |
| Pool scrub schedule | ✅ | ⚠️ PVE default monthly cron | API `/pool/scrub` | existing cron/timer |
| **SMART monitoring** | ✅ | ❌ install `smartd` | API `/smart` | apt + `smartd.conf` |
| Cloud sync/rclone | ⚠️ Cloud Sync (raw rclone preferred) | ❌ install `rclone` | container/Job | apt + systemd timer |
| Alerts/notifications | ✅ | ⚠️ PVE notify | API | n/a |
| Config storage | DB objects | files | API | templates |

## Same intent, different implementation

| Intent | Proxmox | TrueNAS |
|---|---|---|
| Publish NFS | `/etc/exports` + `exportfs -ra` | NFS share object (API) |
| Publish SMB | `smb.conf` + `smbpasswd` | SMB share + account (API) |
| Data holder | ZFS dataset (local) | ZFS dataset (local) |
| Point-in-time | `zfs snapshot` + timer | Pool snapshot task |
| Integrity | scrub cron/timer | Pool scrub schedule |
| Disk health | `smartd` | built-in SMART + tests |
| Guest datastore | local `zfspool`/`dir` on the Proxmox host | Proxmox mounts TrueNAS via **NFS/iSCSI** |

## Bare-minimum bootstrap (before IaC takes over)

**TrueNAS (`zunesha`)** — smallest click-set:
1. Install TrueNAS from ISO.
2. Console first-boot: admin password, hostname, static IP.
3. Enable SSH **or** create an API key (one secret) for the control plane.

→ then pool import/create, datasets, shares, users, snapshots, SMART and rclone are all IaC via the API.

**Proxmox (`atlas`)**:
1. Install Proxmox VE from ISO.
2. Root password, hostname, static IP.
3. Add the control-plane SSH key + switch to the no-subscription repo.

→ then IaC does packages, pool/datasets, share paths, exports, Samba, users, SMART and backup timers. `atlas` itself enters the inventory as a `topology.nodes` entry, so `proxmox_node` is generated, not hand-added.
